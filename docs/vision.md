# S-BOT 蓝图

> 本文档描述 S-BOT 的长期愿景、产品蓝图，以及「开源与商业」的边界。
> 它是给团队、投资人和社区看的「为什么」，不是功能清单。

---

## 愿景

**让每个人都能雇佣一群真正能干的 AI 同事，而不是拥有一个会聊天的窗口。**

今天，人用 AI 大多是「问一句、答一句」。我们相信下一个形态是：人组织起一群有角色的 AI 同事，和真人一起，把事情**做完**——讨论、评审、拆任务、动手执行、交付结果。

## 价值主张

一句话：**用户不为 token 付费，为「事情做完了」付费。**

- token 是燃料，不是价值；
- 价值是「结果」：任务被拆解、被评审、被执行完、被确认；
- S-BOT 的独特之处，是 AI 同事**能协作、能执行、能交付**，不只是能回答。

## 三阶段蓝图

| 阶段 | 形态 | 核心能力 | 状态 |
|---|---|---|---|
| **一 · 本地工作台** | 桌面应用 | 智能体 + 群聊 + 任务 + 执行引擎，本地优先、内网可用 | ✅ 当前（开源） |
| **二 · AI 同事市场** | 平台 + 客户端 | 雇佣「成熟」的 AI 同事：角色 + 技能 + 工作流，一键雇佣、可评价 | 🚧 下一步 |
| **三 · 订阅服务** | 云端 | 托管模型 + 团队协作 + 跨端同步 + 私有化部署 | 🗺️ 规划中 |

## 二阶段：AI 同事市场（核心）

### 什么是「成熟的 AI 同事」

不是一段 prompt，而是一个**能在新环境里跑通、交付结果的能力包**：

```
AI 同事包 = 角色定义 + 技能(SKILL.md) + 工作流(流程图) + 执行许可边界 + 使用说明
```

- **角色定义**：它是什么、擅长什么、说话风格、边界；
- **技能**：它掌握的可复用操作（SKILL.md，可执行）；
- **工作流**：它在群聊里怎么协作（谁先做、要不要评审、改几轮、谁拍板）；
- **执行许可**：它能动哪些文件、跑哪些命令的边界。

### 成熟度如何度量（信誉体系）

「成熟」不能靠作者自吹，要靠可量化的数据：

- 被雇佣次数、复雇率（用户用了一次还想再用）；
- 任务完成率（它接的任务有多少真的做完了）；
- 评价（雇佣者的评分和评论）。

没有这套信誉，「雇佣」就是 GPT Store 的老路——一堆低质量 agent 淹没少数好 agent，用户被坑一次就再也不信。

### 雇佣机制（两种）

1. **复制（免费/低价）**：把人设 + 技能抄走，自己调。→ 引流、养生态。
2. **托管（订阅）**：作者持续维护、更新，按次 / 按月付费雇佣，带版本和评价。→ 现金流。

### 分成与激励

- 作者对「托管雇佣」的收益分成；
- 平台对「信誉 + 分发 + 托管」收费；
- 冷启动：平台先孵化一批「明星 AI 同事」（产品经理、架构师、桌面管家、数据巡检员……），让新用户先雇现成的，用出效果，再引导他们自己调教、分享、变现。

## 开源与商业边界（如何避免「拿来即用」）

S-BOT 采用 **Open Core + 服务化**，边界刻意画得很清楚：

### 开源的部分（给你用、给你改、给你再分发）

本地工作台的全部客户端代码：

- 智能体、群聊、任务、执行引擎集成、内网发现；
- 你可以 `clone`、`npm install`、`npm run dev`，用你自己的 API Key 立刻跑起来。

### 不开源的部分（核心价值，留作商业模式）

「AI 同事市场」的服务端：

- 雇佣、评价、信誉、托管、分成；
- 这是「雇佣成熟的 AI 同事」的价值所在，也是产品能持续迭代、作者能持续维护的现金流来源。

### 协议

**AGPL-3.0**。开源代码你可以自由使用、修改、再分发；但如果你基于它提供了网络服务，也需要以同样的协议开源你的改动——防止「拿来即用、闭源商用」的白嫖。

### 为什么这样设计

> 代码送你，土壤给你，收成（雇佣市场）留给我们一起滚大。

- 客户端开源 → 低成本拉新、快速建立信任和生态；
- 核心价值服务化 → 保护商业模式的护城河；
- AGPL → 法律上挡住「拿走闭源卖服务」的白嫖。

---

## 从代码到「收成」的路径

1. 开源客户端 → 用户本地跑起来、调教出自己的 AI 同事；
2. 用户沉淀出「成熟的 AI 同事」→ 分享到市场；
3. 后来者「雇佣」→ 作者分成、平台收费；
4. 现金流反哺 → 继续迭代客户端、扩大生态。

这是一个「开源长生态 → 生态产价值 → 价值养产品」的正循环。
